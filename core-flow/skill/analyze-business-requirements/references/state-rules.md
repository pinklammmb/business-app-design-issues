# 槽位状态与澄清矩阵

## 四态

| 状态 | 含义 |
| --- | --- |
| resolved | 用户已说清，或有上下文依据可推导，足够确定 |
| partial | 已提及但无法合理推断，且缺少必须由用户决定、会实质影响业务的信息 |
| missing | 本次全部有效文本未提供信息，且无法依据输入推导 |
| conflict | 排除明确修正和兼容补充后，同一定位、同一条件下的有效要求无法同时成立，且无法确定替换关系 |

每条定位记录独立判断，无槽位总状态。未提及不等于不需要，明确无需某项能力可为 resolved。

状态判断以业务意图为准，不要求用户补全所有配置。先提取和尝试推断，再识别实际缺口。字段长度、图表布局等常规细节不生成 partial；不得擅定审批阈值、审批人或权限边界。

先识别用户是否明确修正，再判断新旧要求可否兼容，最后判冲突。明确取消或只保留时替换旧要求并撤销失效冲突；兼容信息合并；不同业务和条件不直接判冲突。不能只因信息更多就判冲突，也不能只因出现得更晚就覆盖旧要求。

## 类别

类别及槽位范围见 [槽位定义](slot-definitions.md)，不得沿用旧版按 20 个槽位的分组。

| 类别 | 含义 | resolved | partial | missing | conflict |
| --- | --- | --- | --- | --- | --- |
| A | 业务描述与规划，无需搭建 skill 执行 | false | true | true | true |
| B | 当前 skill 和接入协议支持 | false | true | false | true |
| C | 当前接入协议不支持，默认不问 | false | false | false | false |

false 不等于已明确，保留实际状态。候选被回答解决或依据可推断时先更新，不重复问。

## 依赖

审批类型未确定或明确无需审批时，不展开该业务的节点名称、节点类型、节点顺序、审批人、抄送、分支、两类节点高级设置和角色权限中的节点字段约束，除非用户已经提供了这些信息。审批生效后仅检查实际相关要求，不将 B 类 missing 全部升级为必问。依赖按业务定位分别判断。

同一事实只归入一个槽位；一段回答包含多个相关事实可以分别提取。附件仅以已提取文本参与判断。
C 类即使 conflict 也不进入追问清单；保留候选和依据，说明待人工确认及影响。关键影响须限制相关应用发布，不能通过静默选择、默认值或删除需求绕过。追问与发布判断分开。
