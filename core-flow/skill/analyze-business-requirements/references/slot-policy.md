# 槽位分类与四态口径

本版按用户最新清单，共28个槽位：A 类4个、B 类17个、C 类7个。分类依据为已核对的 form-create、approval-create、chart-create 及当前接入协议，尚未完成端到端实测。分类表示信息用途和本流程自动搭建范围，不表示平台全部能力，也不表示已创建或发布。

- A 类：业务名称、环节、角色及对象规划。先提取并有据推断；仍partial、missing或conflict时需澄清。
- B 类：本次搭建规格。已提出但缺关键业务决定或存在冲突时澄清；missing不批量追问，常规设计可由AI补齐并标记来源。
- C 类：当前不自动配置，partial、missing和conflict默认均不追问。保留原要求及影响，相关关键权限或校验未补齐时仍限制发布。

四态与分类独立：resolved表示信息已具体，partial表示已提及但缺关键决定，missing表示未提供且无法推导，conflict表示排除明确修正和兼容补充后仍不能同时成立。低风险AI设计补全以依据来源标记，原文可为null、推导理由必填；不冒充用户确认。每条记录独立判态，ID稳定。

## 归并边界

菜单导航不再拆结构与实际配置，统一为C类“菜单导航设计”。应用绑定组织架构统一为C类；这不取消B类审批节点对已有主管、角色的引用，也不允许编造真实组织映射。节点内字段权限并入C类“角色权限”，不再单列槽位。

不再单列旧“其他能力要求”。已有提醒、业务联动、报表、集成等扩展需求，按其业务目的保留到对应“业务环节”记录的已知信息、依据和约束说明中，不丢失原文。仅对业务目标本身不清或冲突按A类判断，不为扩展的技术实现细节发起默认追问；未明确提出的扩展不主动增加，是否影响当前应用发布按实际影响判断。

字段选项值仍为C类，名称、类型和顺序仍为B类。AI设计补全必须标明来源并被计划requirement_ids关联，不能将未支持要求记为已自动完成。
