# 业务系统建设方案对话修改

## 输入与意图

输入为对应版本的完整业务系统建设方案、完整有效需求、用户本次修改及可选针对性回答；不靠聊天记忆恢复事实。仅询问现有方案含义时用 unchanged 返回解释，不修改需求或业务系统建设方案。

允许新增业务、删除对象、改变流程、字段、指标、导航或权限，以及纯措辞调整。澄清阶段 deferred_content 只有用户在此明确提出或采纳才并入，不能自动采纳全部暂存内容。

## 处理顺序

1. 定位修改目标。指代不明且不同解释实质影响方案时提问；能唯一定位则直接处理。
2. 明确修正或取消则替换旧要求，兼容补充则合并。不能按时间自动覆盖：同条件互斥且无法确定替换关系时才判冲突，保留双方依据。
3. 先由计划项的 requirement_ids 找到输入快照的槽位记录，在 requirements_input 工作副本更新本次相关记录及依据，保留 ID；新增需求按现有槽位新增记录并分配新 ID。未命中计划不等于无效需求；方案独有内容可直接匹配槽位。按 application-build-plan.md 处理所有未匹配情况。新增明确要求标“用户明确”，来源引用本次消息标识与原文；推导标“依据推导”并写理由。“不做审批”改为需要审批，应撤销失效排除项。AI 设计细节留在业务系统建设方案补全区，不冒充需求事实。
4. 更新受影响章节与图表。对象改名同步导航、字段引用、审批、指标、权限及实施项；移除审批同步清理失效节点及依赖；删除字段检查公式、图表和分支；权限改动分别核对菜单、数据、字段和功能权限。
5. 只删除本次变更导致失效且无其他用途的设计。删除对象会破坏仍有效业务时，说明冲突并提问，不能自行扩大删除范围或丢弃原需求。
6. 按是否仍有可识别业务意图更新可生成标记及未决影响，不以关键细节齐全作为出图条件。只针对本次修改的必要歧义提问；其他未知写入对应位置及第 9 章，关键未知注明执行限制，不用默认值消除。
7. 按 application-build-plan.md 使用 requirement_ids 同步更新受影响计划项，保留无关内容和稳定 ID。更新完整正文、做跨章节及计划一致性校验，输出完整新需求、业务系统建设方案和应用搭建计划；changes 只简述实际修改及关联影响。

## 必要提问与提交

必须遵循 [对话修改追问规则](revision-questions.md)，所需判态、出题和回答处理规则均在本包 [追问设计](question-design.md) 中定义；对话修改不设总轮次上限。用户首轮及后续新修改在输入框输入；追问占用输入框区域显示问题卡片，更新完成再恢复输入框并询问是否进入搭建。

- C 类配置细节默认不问，包含字段选项值及其冲突；按 slot-policy.md 保留候选与人工补齐影响。只在无法理解本次修改目标时确认操作意图。
- 本阶段可以持续修改和必要追问，无三轮上限；只处理本次变更及依赖，不扫描全量需求找新问题。每轮 ready 或 unchanged 后，前端再次提供“按计划搭建”，否则用户继续输入需求。只有用户主动确认最新已保存计划才进入搭建。
- “加审批”无法确定办理人且影响核心路径时，只问办理身份等必要信息；“改为管理员审批”不再问是否修改。
- needs_input 不提交部分修改：返回原 requirements_input、原业务系统建设方案和原应用搭建计划，changes=[]，questions 列具体问题；message 说明哪些修改待同批处理。
- 后端暂存原 change_request、问题及回答；补充调用仍用 revise，携带同一当前版本、完整原修改请求及累计有效回答，不依赖对话记忆。
- 用户取消时返回 unchanged。多项修改存在关键歧义时整体等待，避免误以为请求已全部生效。
- 重复请求、纯咨询或无变化返回 unchanged，不生成新版本、不重置确认。ready 表示可评审，不表示已获用户确认。

## 行为示例

| 当前方案与用户输入 | 应有结果 |
| --- | --- |
| 不做审批；“改为管理员审批通过后生效” | 替换旧排除项，更新流程和状态，不重复问是否审批 |
| “管理员审批”；“管理员和主管都要审批” | 合并参与者；顺序存在实质缺口时仅问顺序，不把增加参与者直接判冲突 |
| “只需管理员且不经过主管”与“必须管理员和主管”，无法判断修正关系 | 说明矛盾并针对提问，不按先后覆盖 |
| “设备台账改名为资产台账” | 同步全部对象引用，保留无关字段和规则 |
| “新增维修申请，员工提交、管理员审批；本人只看本人申请” | 增加有效需求和必要设计；管理员数据范围未明确则保留待确认，不默认全部授权 |
| “删除申请金额”，金额分级审批仍有效 | 问如何调整原分支，不直接删除分支 |
| “为什么要有登记人字段？” | unchanged，解释本人数据范围识别依据，不删除字段 |
| 暂存维修需求，用户只要求改表名 | 只改名，不自动采纳维修业务 |
