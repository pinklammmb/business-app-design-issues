# 应用搭建计划与槽位关联

完整字段与类型见本包 [应用搭建计划结构](application-build-plan-schema.md)。

application_build_plan 是独立结构化计划，按下面四个数组输出：forms、approvals、dashboards、pending_items。不另建映射表；应用及子项内的 requirement_ids 直接引用 requirements_input.槽位分析 中的记录 id。搭建调用方直接消费本计划，并通过同版槽位快照补齐执行细节；本计划不是平台配置 JSON，prepare 只将其校验转换为任务结构，不再读取建设方案章节。

## 简短示例（节选）

```json
{"approvals":[{"id":"a1","name":"资产领用申请","requirement_ids":["s01"],"fields":[{"id":"f1","name":"领用数量","type":"数字","requirement_ids":["s02","s03"]}],"nodes":[{"id":"n1","name":"部门主管审批","requirement_ids":["s05","s06"]}]}]}
```

正式计划四个数组必须齐全；示例 ID 只演示关系，实际每个引用必须在本次需求快照中存在。

## 项目结构

- forms 每项：id、name、requirement_ids、fields。字段每项：id、name、type、requirement_ids。
- approvals 每项：id、name、requirement_ids、fields、nodes。节点每项：id、name、requirement_ids，按审批顺序排列，不展示办理身份配置，但关联时包含支撑节点的审批人、顺序等记录。
- dashboards 每项：id、name、requirement_ids、charts。组件每项：id、name、type、requirement_ids；不展示数据源、维度、指标和聚合配置，但已有相关需求记录仍应关联，避免修改后漏更新依赖。
- pending_items 每项：target_id、requirement_ids、requirement、reason、impact。target_id 指本计划应用或子项 id；只有明确约束本次计划全局时才可为 null，不能用 null 掩盖定位不清。只列影响当前计划的待确认和人工补齐事项，不把 C 类功能写成自动实现承诺；仅属完整方案的独立扩展能力保留在需求和方案中，不强加为本次搭建应用。

应用及子项 id 是计划内稳定标识，改名或修改时沿用；新增分配新 ID，删除不复用。requirement_ids 是非空、去重的记录ID数组；必须引用同版本快照中存在的记录，不能使用名称、位置或数组下标替代。AI补充的常规设计先按 blueprint-input.md 写入有来源标记的具体槽位记录，再关联该记录和必要业务依据，不伪造用户确认。尤其审批身份、源对象、维度、指标、聚合等执行必需信息，必须能由关联快照确定；不得仅写在正文。信息不足时保留待确认，不留给配置生成时重新自由设计。

## 修改顺序

1. 从用户意见定位已有计划项，通过 requirement_ids 找到原需求；明确变更只修改对应记录，不能重跑全量分析或覆盖未改变的已确认要求。
2. 更新相关计划项及其必要依赖，其他项的 ID、顺序、内容保留。
3. 完整建设方案跟随最新需求与计划更新，不保存段落映射。涉及方案独有的扩展内容时直接更新对应槽位和方案，不要求一定命中计划。
4. 输出完整新需求、计划和方案，后端原子保存同一版本；校验失败或 needs_input 时不提交局部结果。

## 匹配不到已有记录

| 情况 | 处理 |
| --- | --- |
| 新需求能归入现有槽位 | 新增定位记录与 ID，再新增或更新计划项；不当成解析失败 |
| 意图明确但原计划无该项 | 从现有槽位查找支撑；若确属新增，创建记录，不强行关联相似旧项 |
| 同名对象或修改指代不清 | 只问本次要改哪个对象，原版本保留 |
| 仅措辞、排版或AI设计表现调整 | 保留原关联；无业务需求改变时不新增槽位事实 |
| 属于完整方案的人工扩展功能 | 更新对应槽位和方案；不加入本次自动搭建承诺 |
| 确实无法归入现有槽位定义 | 保留原请求，返回 needs_input 说明无法归类并确认含义；不丢弃，不臆造类别，不随意归入业务环节或其他槽位。若定义确需扩展，先维护规范再提交该变更 |
| ID 引用缺失或跨版本 | input_error，要求调用端补齐正确快照；不猜测或自行换绑 |

前端只展示表单名称与字段类型、审批名称与字段类型及节点、仪表盘名称与组件名称及类型；id、requirement_ids 仅作为后台元数据，用户方案正文、页面及下载文件都不含这些ID。
