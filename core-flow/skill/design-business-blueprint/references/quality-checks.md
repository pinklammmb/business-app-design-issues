# 输出前质量检查

1. **输入与范围**：仅使用有效需求，明确排除项未进入方案；未决事项没有被默认值抹除；示例角色和对象没有被带入。
2. **来源**：用户明确、已有推导、本次 AI 补全的标记准确；补全有理由，未编造用户确认。
3. **完整性**：需求中的业务、角色、数据、流程、指标、权限和可选能力均有对应设计或明确限制；重要条件、数值和精度未被概括丢失。
4. **引用**：导航、模块图、表单、审批、仪表盘、权限及可选能力中的对象名称和类型与第 2.3 节一致；被用到的字段存在于对应字段表。
5. **流程**：审批判定与对象类型一致，分支有已知去向；未知关键条件未伪造；待确认路径没有被写成可以直接执行。
6. **权限**：菜单与应用权限分开，角色和数据范围有依据；示例“全部字段”未自动变为授权；真实成员未编造。
7. **平台约束**：按 slot-policy.md 核对分类，字段选项值为 C 类；C 类冲突保留候选不擅选，不为收集其细节追加追问。字段类型在白名单内，枚举已知值完整，日期精度明确；未确定内容明确标记，未用省略号代替实际内容。
8. **实施**：完整建设方案与自动实现范围分开；未实现要求有原设计、影响与人工补齐方式，关键缺项明确禁止相关应用发布，不因能力不足裁剪需求或虚报完成。
9. **应用搭建计划**：application_build_plan 单独输出；字段名称、类型、审批节点、仪表盘名称及组件名称和类型具体且与正文一致；计划不包含办理身份、数据源、维度、指标或聚合配置，requirement_ids 均指向同版存在的槽位记录，稳定 ID 唯一，用户正文和下载内容不含内部ID；修改仅影响本次关联及必要依赖，其余项目保留。待确认与 C 类要求不被写成已实现或可自动搭建。执行所需的具体设计可通过关联快照取到；AI设计补全有明确来源，不仅存在于正文。
10. **Markdown**：按规模保留正确章节及编号，无未替换的模板占位符，无空壳对象；图与表一致，Mermaid 节点标识与中文标签分开；不将全文再包入代码围栏。

可自行修正名称、引用、排版与常规设计问题；需要用户决策的信息不擅填。局部问题显式记录。generate 仅无可识别业务意图时按调用契约返回 blocked；存在业务意图时，依据已有信息生成方案，关键未知显式标注待确认及执行限制，不新增追问；revise 的必要歧义或冲突按修改规则返回 needs_input，不重启全量澄清。
## 对话修改附加检查

- 有效需求、明确排除项、未决事项与业务系统建设方案同步；取消要求未恢复，暂存新业务未自动采纳。
- 对象改名、字段删除、审批和权限变化的依赖引用均已检查，未触及无关设计。
- needs_input 题型、选项、答案及去重规则符合 revision-questions.md；没有三轮上限、不重复已解决问题；ready/unchanged 后恢复输入框并再次提供按计划搭建。needs_input 和 unchanged 保留原需求、原业务系统建设方案；blocked 候选诊断不覆盖正式版本。
- ready 返回完整新需求、完整业务系统建设方案及完整应用搭建计划，changes 对应实际修改；未替用户确认。
- JSON 可解析，status 与字段条件符合契约，Markdown 正文没有被截断或替换为差异片段。
