# 部分实现与发布控制

业务系统建设方案是整体建设方案，自动搭建只实现当前协议支持的部分。保留完整业务系统建设方案和原始任务要求，不因暂时不能自动配置就删减方案，也不把未实现要求记成已实现。

## 槽位分类与需求状态

按 [槽位分类与四态](slot-policy.md) 解释需求：A 类提供上下文，不计作已搭建；B 类按协议实现；C 类保留原要求，其中属于本次计划或影响本次应用的内容进入 todos；独立未来扩展按下文范围规则处理。字段选项值为 C 类，不能自造 options 等协议键。四态 resolved 只说明需求明确，不说明协议支持；partial、missing、conflict 不能被配置默认值抹去。C 类默认不追问，冲突保留候选，不能任意选择；按实际影响控制相关应用及依赖的发布。

## 生成与发布分别判断

| 情况 | 配置结果 | 发布处理 |
| --- | --- | --- |
| 已支持要求全部实现 | config_ready，返回有效配置 | publish_allowed=true，publishImmediately=true |
| 存在可后补的普通缺项，其余功能可正确运行 | config_ready，返回已支持部分与 todos | publish_allowed=true，publishImmediately=true |
| 可生成有效配置，但缺项影响关键业务行为 | config_ready，返回供补齐或预览的配置与 todos | publish_allowed=false，publishImmediately=false；后端禁止发布或启用 |
| 无法形成结构合法且有实际用途的配置 | blocked，config=null，保留 todos 与原因 | publish_allowed=false |
| 所依赖的运行结果尚未返回 | waiting，config=null | publish_allowed=false |

config_ready 只表示有合法配置，不表示完整实现、允许发布或已经保存。关键缺项未消除时，false 不能因重试或点击“开始搭建”被改为 true。不能依赖创建页记住本次开关，后端也须阻止另一路手动或自动发布；人工补齐并核验后才解除限制。

## 缺项分级

- 普通缺项：不改变已支持业务的含义、执行路径、关键数据正确性或授权边界。例如纯展示布局、非关键字段的展示默认值、独立附加统计组件。
- 关键缺项：审批人或必要审批路径、权限或敏感字段边界、决定业务结果的校验/计算/公式、库存/额度等限制、关键关联及其必要数据。例如缺金额分支不能改成单一路径后发布，缺库存校验不能放任超额领用。
- 必填、默认值、选项、公式等不能仅按属性名统一分级，要看它是否改变本项业务结果。无法判断影响时按关键缺项处理，不默认为普通。
- 不生成协议外字段、不虚构真实人员/字段 ID、不将未知数据类型一律改成文本、不用错误指标替代缺失指标。只输出协议合法的已支持部分。
- 可用字段、节点或图表可独立生成；若移除不支持部分后破坏引用或流程结构，应进一步移除依赖项并列入待办，无法形成有效配置才 blocked。只影响相关应用及其实际依赖，不终止其他独立任务。

## 未完成项 todos

generate_config 与 summarize 都返回 todos 数组，每项固定为：

```json
{
  "target":"app_1 / 申请单 / 金额分支",
  "requirement":"金额超过一万元须由部门主管审批",
  "reason":"当前审批接入协议未定义条件分支配置",
  "impact":"不能保证申请进入正确审批路径",
  "follow_up":"实施人员在该审批应用的流程配置中补齐分支并核验",
  "blocks_publish":true
}
```

target 定位应用及具体要求，无法自动搭建的独立能力也可用其名称定位。requirement 保留业务系统建设方案原要求；reason 区分协议未定义、当前实现不支持或依赖缺失，不能断言平台不存在该能力；impact 写明实际影响；follow_up 写补齐位置与动作，不编造具体操作页名称、负责人姓名或不存在的接口。无法确定页面时写“在平台对应配置入口核实并补齐”。

blocks_publish 为布尔值，仅表示是否禁止相关应用发布。todos=[] 才可能表示本次传入要求无待办；空数组不代表整个业务系统建设方案全部实现。issues 仍用于输入错误、歧义与运行诊断，不能用一个泛化 warning 代替具体 todos。

## 当前搭建范围与未来扩展

本次计划外、与当前应用正确性和权限无依赖的未来扩展，仅保留在完整方案和 scope_notes，不加入当前 todos，也不因此把本次搭建判为 partial。相反，本次应用要正确使用所必需的权限、校验、审批路径等即使由人工补齐，也必须进入当前 todos 并执行发布限制。overall 只评价已确认搭建计划及其必要待办，不代表完整建设方案的所有未来功能已实现。

## 交付

交付包含完整业务系统建设方案、实际已创建应用及未完成清单。汇总 config_results 中全部未完成项，结合人工补齐核验结果只移除已解决项；不得因应用已发布或有访问地址就清空普通待办。

summarize 的 overall=complete 要求范围内所有应用均已发布且 todos、阻塞问题均已解决。有已创建但未全部完成的成果（包括已发布但有普通待办，或配置已应用但待补齐才能发布）为 partial；没有实际应用成果为 incomplete。仅打开空白创建页、JSON回显预览、空白壳或模型配置均不算实际完成成果；表单/审批的configured只说明回显，不自动算作已创建应用。

计划外人工实施项由调用方从同版已保存应用搭建计划与槽位约束提供为 manual_todos，格式相同；prepare 保存进 plan.manual_todos，生成前检查与目标相关的关键待办并带入生成结果，summarize 汇总全部剩余项。不要求本 skill 重读全文。未提供时仅汇总本次任务范围，并在 scope_notes 保留范围限制；后端不能据此跳过已知的关键权限/业务发布门槛。
